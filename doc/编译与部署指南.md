# cursor-byok 编译与部署指南

> 适用仓库：`keylei/cursor-byok`（本地位于 `tmp/server/cursor-byok`，供后续按需修改参考）。
> 官方文档：[User Guide](https://docs.leokun.cn)。本文只整理**源码编译 + 本地部署使用**路径，面向要自己改代码的场景。

## 主要结论

- **项目形态**：Rust Cargo workspace，含一个 Tauri 桌面应用（`apps/desktop`）和一个独立的网关服务库/二进制（`server`）。
- **普通使用**不需要编译，直接下载 Release 装包即可。
- **改代码调试**只需编译 `cursor-server` 这一个二进制，不需要装 Tauri 全套环境。
- **打完整桌面安装包**才需要 Tauri 构建依赖（WebView2、MSVC、Node 前端构建）。
- 核心机制：本地跑一个 HTTP 服务伪装成 Cursor 后端，再用本地 CA 证书 + HTTPS 代理把 Cursor 客户端的请求拦截转发到自己配置的模型 API。

## 一、项目结构

```text
cursor-byok/
├── apps/desktop/           # Tauri 桌面前端 + 外壳
│   ├── src/                 # React 前端（模型设置、首页、调用记录等页面）
│   └── src-tauri/           # Tauri Rust 外壳，内嵌 cursor-server 作为依赖库
├── server/                 # 核心网关服务（Rust library + bin）
│   ├── src/bin/cursor-server.rs   # 独立运行入口（非桌面模式）
│   ├── src/cursor/          # Cursor 协议适配层
│   ├── src/provider/        # OpenAI / Anthropic 等上游协议适配
│   ├── src/local_app/       # 本地 CA、HTTPS 代理、Cursor 配置注入
│   ├── src/control/         # 管理面 API（桌面前端调用）
│   └── src/store/           # SQLite 持久化（模型配置、设置）
├── crates/semble-core/      # 本地代码语义索引库（供 Agent 搜索工具使用）
├── protocols/cursor/        # 逆向得到的 Cursor 协议定义（唯一来源）
├── support/                 # 协议抓取、提取、基准测试等辅助工具
├── Cargo.toml               # workspace 定义
├── Makefile                 # 常用构建命令
└── Dockerfile               # cursor-server 的容器化构建（不含桌面壳）
```

## 二、两种运行形态

| 形态 | 二进制 | 用途 |
|---|---|---|
| **桌面应用** | `cursor-byok-desktop`（Tauri） | 普通用户使用，带 GUI，自带 CA 安装引导、模型设置面板 |
| **独立服务** | `cursor-server`（纯命令行） | 自托管 / Docker 部署，无 GUI，靠环境变量配置，给桌面前端当静态文件服务器用 |

两者共用同一份 `server` 代码（`apps/desktop/src-tauri` 以路径依赖的方式引用 `server` crate）。**改网关逻辑、协议适配，只用改 `server/src/` 下的代码，两种形态都会生效**。

## 四、只改网关逻辑：编译独立服务（推荐，最省事）

不涉及 Tauri、不需要前端构建，编译速度快，适合改 `server/src/provider`、`server/src/cursor`、`server/src/local_app` 等逻辑后快速验证。

```powershell
cd C:\code\sln\wmi\tmp\server\cursor-byok
cargo build --release --package cursor-server --bin cursor-server
```

产物：`target\release\cursor-server.exe`

### 运行（命令行模式）

该二进制依赖的配置项全部来自环境变量（`server/src/config.rs`）：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `CURSOR_LISTEN_ADDR` | `127.0.0.1:3000` | 监听地址 |
| `CURSOR_DATABASE_URL` | `~/.cursor-byok-v3/cursor-byok.db` 对应的 sqlite URL | 模型配置、设置持久化位置 |
| `CURSOR_PROVIDER_TIMEOUT_SECONDS` | 3600 | 转发到上游模型 API 的请求超时 |
| `CURSOR_CONSOLE_DIR` | 无 | 静态文件目录，用于托管前端产物（和 `CURSOR_CONSOLE_PROXY` 二选一） |
| `CURSOR_CONSOLE_PROXY` | 无 | 开发模式下把管理面请求反代到 Vite dev server（和 `CURSOR_CONSOLE_DIR` 二选一） |

最小启动（只跑网关，不带管理面 UI）：

```powershell
$env:CURSOR_LISTEN_ADDR = "127.0.0.1:3000"
.\target\release\cursor-server.exe
```

健康检查：

```powershell
curl http://127.0.0.1:3000/__byok-api__/healthz
```

### 配合前端一起跑（联调模式）

仓库自带联调脚本（`apps/desktop/package.json` 的 `dev:web`），会同时起 `cursor-server`（反代管理面到 Vite）和前端开发服务器：

```powershell
npm --prefix apps\desktop install
npm --prefix apps\desktop run dev:web
```

浏览器打开 `http://localhost:1420` 即可看到和桌面应用一致的管理面 UI（模型设置、Cursor 接入状态等）。

## 五、打完整桌面安装包（Windows）

需要完整 Tauri 构建链，流程较长，适合要分发安装包给别人用的场景。

```powershell
cd C:\code\sln\wmi\tmp\server\cursor-byok
npm --prefix apps\desktop install
make build-desktop
```

`make build-desktop` 做了两件事（见 `Makefile`）：

1. 自动生成一对本地临时 Tauri 签名密钥（`.tauri\cursor-byok.local.key`），用于 Tauri 的自动更新签名校验（本地构建不需要真正发布更新，用临时 key 即可通过签名校验）。
2. 调用 `tauri build --bundles nsis`，产出 Windows NSIS 安装包。

产物位置：`apps\desktop\src-tauri\target\release\bundle\nsis\*.exe`

> 注意：`tauri.conf.json` 里的自动更新检查地址已改为指向本仓库的 GitHub Release（`keylei/cursor-byok/releases/latest/download/latest.json`），`apps/desktop/src-tauri/src/update/mod.rs` 中的便携版更新地址同理。目前本仓库没有任何 Release，更新检查会直接失败（无害）；若将来要自行发布，需要用 `tauri signer generate` 生成自己的签名密钥对，并把 `tauri.conf.json` 里 `plugins.updater.pubkey` 换成自己的公钥，否则签名校验通不过。

## 六、Docker 部署（自托管独立服务，不含桌面壳）

`Dockerfile` 只构建 `cursor-server` + 前端静态文件，不含 Tauri，适合部署在服务器上长期跑，通过浏览器访问管理面。

```powershell
cd C:\code\sln\wmi\tmp\server\cursor-byok
docker build --tag cursor-byok:local .
docker run -d --name cursor-byok -p 3000:3000 -v cursor_byok_data:/data cursor-byok:local
```

镜像内置的默认环境变量（见 `Dockerfile`）：

```text
CURSOR_LISTEN_ADDR=0.0.0.0:3000
CURSOR_DATABASE_URL=sqlite:///data/cursor-server.db
CURSOR_CONSOLE_DIR=/app/console
RUST_LOG=cursor_server=info
```

容器自带 `HEALTHCHECK`，打 `/__byok-api__/healthz`。数据（模型配置、设置）落在 `/data` 挂载卷，容器重建不丢失。

浏览器访问 `http://<部署机器IP>:3000` 即可打开管理面，和桌面应用的配置界面一致。

> Docker 部署模式下**没有本地 CA 证书注入和 HTTPS 代理拦截这一套**（那部分逻辑是桌面应用专属，见下一节），只提供网关 API，需要配合其它方式让 Cursor 把请求打到这个地址，不是开箱即用的 Cursor 接入方案，更适合当纯模型网关用。

## 七、工作原理（为什么必须是桌面应用才能"接入 Cursor"）

```text
Cursor 客户端
    │ HTTPS 请求（被本机 http.proxy 指向本地代理端口）
    ▼
cursor-byok 本地 HTTPS 代理（hudsucker，自签 CA）
    │ 解密后按 host 判断是否是 Cursor 域名，转发给本地管理服务
    ▼
cursor-byok 本地管理服务（cursor-server，监听 127.0.0.1:随机端口）
    │ 按配置路由：官方请求直通 / BYOK 请求本地处理
    ▼
你配置的模型 API（OpenAI / Anthropic 兼容）
```

关键代码位置：

- `server/src/local_app/ca/`：生成/安装本地根证书到系统信任库（`windows.rs` 走 Windows `CertOpenStore` API 写入 `LocalMachine\Root`）。
- `server/src/local_app/proxy.rs`：基于 `hudsucker` 库启动本机 HTTPS MITM 代理，拦截 Cursor 域名流量。
- `server/src/local_app/settings.rs`：修改 Cursor 的配置文件，把 `http.proxy` 指向本地代理端口。
- `server/src/local_app/process.rs`：应用代理设置前尝试终止 Cursor 进程，让新配置生效更快。

这一套**依赖本地系统权限**（写系统根证书、改 Cursor 配置文件、可能需要管理员权限终止/重启进程），只有桌面应用（Tauri 外壳提供系统 API 访问）才方便做，纯 `cursor-server` 命令行二进制或 Docker 容器做不到，因此：

- 想要"让 Cursor 客户端直接用上"：必须用**桌面应用**（方式一或方式五打出来的安装包）。
- 想要"只要一个模型网关 API，自己手动配置代理指向它"：可以用**独立服务**（方式四或方式六），但接入 Cursor 需要自己手动改 Cursor 配置或系统代理设置。

## 九、后续按需修改时的建议落点

| 想改的东西 | 看这里 |
|---|---|
| 支持的模型协议 / 请求转发细节 | `server/src/provider/` |
| Cursor 协议本身的适配（工具调用、多轮对话） | `server/src/cursor/`、`protocols/cursor/` |
| 本地 CA / HTTPS 代理行为 | `server/src/local_app/` |
| 管理面 API（桌面前端调的接口） | `server/src/control/` |
| 配置项、环境变量 | `server/src/config.rs` |
| 桌面 UI（模型设置页等） | `apps/desktop/src/features/` |
| 窗口、托盘、更新逻辑 | `apps/desktop/src-tauri/src/` |

修改后优先走第四节的"只编译独立服务"流程验证，确认逻辑没问题后再考虑是否需要打桌面安装包。
